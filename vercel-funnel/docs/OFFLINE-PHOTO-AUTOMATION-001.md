# OFFLINE-PHOTO-AUTOMATION-001 — облачная обработка фото тестов

Действующая Trainer-воронка и webhook сохраняют прежние адреса, статусы и обработчики. В группе `-1004397133749`, теме `1071`, бот принимает фото от любого участника и сохраняет оригинал в Drive `offline test`. Каждое `(chat_id,message_id)` обрабатывается один раз.

После сохранения бот ставит защищённую облачную задачу через уже действующий планировщик Trainer. Через три минуты Google Drive OCR читает рукописный текст. ФИО сверяется с единственной карточкой `candidates`/`applications`; обнаруженный телефон обязан совпасть с номером карточки. Дата теста берётся из рукописного листа, а город — из карточки кандидата; если OCR различил город на листе, он должен совпасть. Противоречие в имени, телефоне, дате или городе удерживает фото без переноса. Для альбома через 12 минут допускается перенос листов без подписи только при одном подтверждённом кандидате и одной дате/городе внутри того же альбома и отправителя.

Подтверждённый оригинал перемещается из временной папки в существующую папку `candidate_drive`; мост проверяет, что папка лежит под Trainer root, сохраняет доступ `anyone with link — reader` и повторно не перемещает уже назначенный файл. Метаданные Telegram, кандидата и фактического теста остаются в `offline_photo_intake_001`. Кандидатские статусы, записи и сообщения кандидатам не меняются.

По каждому подтверждённому фото назначается бриф через 60 минут. Пара `(фактическая дата теста, город)` имеет единственную запись `offline_photo_briefs_001` и один ID сообщения бота в теме. Поздний лист редактирует этот же бриф. Новый город в тот же день получает отдельный бриф. В тексте имя и прямая ссылка Google Drive идут соседними строками, а пустая строка стоит только между кандидатами. При неясном ответе Telegram отправка не повторяется автоматически, чтобы не создать дубль.

Бриф 14.09.2026, Минск, опубликован ранее аккаунтом владельца как сообщение `1344`; Bot API не может редактировать его. Автоматические будущие брифы создаёт бот. Если за историческую дату появятся новые подтверждённые фото, бот создаст отдельное собственное сообщение этой даты и затем будет редактировать его.

Проверка: Apps Script версия 7 OCR прочла имя, дату и телефон на сохранённом образце. Версия 8 сохранила прежний URL; прямой тест функции подтвердил `alreadyAssigned=true`, а защищённый Vercel preview вызвал опубликованный bridge и получил такое же подтверждение. Облачный worker проверен на синтетической базе: перенос, отсутствие изменения статуса кандидата, один бриф, его редактирование при позднем добавлении и отдельный бриф другого города. Реальное фото нового участника после server release ещё требуется наблюдать для окончательной приёмки.
