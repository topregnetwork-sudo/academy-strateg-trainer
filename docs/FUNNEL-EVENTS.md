# CANDIDATE.DECLINED — последствия041

Ручной статус cancelled в панели либо «не актуально» в боте вызывает lib/candidate-decline.js. В одной транзакции: зафиксировать старые данные в candidate_decline_events, убрать будущие резервации из активных таблиц (полные строки остаются в снимке), cancelled+consent=false, создать одну точную задачу candidate_declined. Прошедшие встречи и остальная анкета не удаляются. Повтор того же отказа использует прежнее событие.

Задача отправляет уведомление об отказе и новую актуальную сводку в служебную тему соответствующей встречи (продуктивность: Координация30; первое Zoom: настроенная тема первичного брифа), обновляет кнопки только у приглашённых без записи. В публичную группу кандидатов персональные брифы не отправлять. Старые сообщения остаются историей. Ручной отказ не пишет кандидату; самостоятельное «не актуально» сохраняет прежнее подтверждение в боте. Ни отмены места при других ручных статусах, ни исключения из группы этим действием нет.

Реальный успех брифа виден в карточке по notified_at; queued не означает delivered. Сбой доставки хранится в событии и журнале точной задачи, не маскируется под несохранённый статус. Ни одного периодического обхода кандидатов. При отмене отзыва/возврате кандидата новая запись требует отдельного действия, не восстанавливать занятое другим место автоматически.
