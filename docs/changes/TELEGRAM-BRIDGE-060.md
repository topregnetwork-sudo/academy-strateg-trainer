# TELEGRAM-BRIDGE-060 — устойчивый переход из Анкеты 1

## Что исправлено

- Убрана зависимость отправки анкеты от прямого Supabase-маршрута, который может быть недоступен без VPN.
- API-маршруты теперь пробуются последовательно с независимым тайм-аутом 9 секунд: текущий сайт, основной Vercel API, резервный Cloudflare Worker.
- После успешного сохранения открывается стандартная Telegram-ссылка с сохранённым deep-link payload.
- Окно Telegram создаётся непосредственно по нажатию кнопки, поэтому его не блокирует popup-защита после ожидания API.
- На странице остаётся понятный резерв: повторное открытие ссылки, Telegram Web и точная команда `/start trainer_app_<код>`.
- Синхронизированы основная и резервная копии `app.js`; добавлено cache-busting `20260902-telegram-bridge-060`.

## Что не менялось

Статусы, слоты, тексты сообщений бота, обработчик `/start`, анкета, панель, базы данных и остальные этапы воронки не изменялись.

## Проверка

- `node --check` для обеих копий `app.js` и API — успешно.
- `git diff --check` — успешно.
- Live GET основного сайта, Vercel и Worker — HTTP 200.
- Реальная отправка анкеты не выполнялась, чтобы не создавать фиктивного кандидата.
- Полный старый набор тестов проекта запускается только частично: несколько тестов используют `mock.module`, которого нет в текущем Node 24, а PGlite завершается ошибкой выделения памяти. Это ограничение тестовой среды, не ошибка данного узла.

## Откат

Точная ветка до изменения: `rollback/telegram-bridge-before-060`.

После публикации откат: `git revert <коммит TELEGRAM-BRIDGE-060> && git push origin main`.
