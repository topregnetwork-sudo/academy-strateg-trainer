# PRODUCTIVITY-OUTCOME-064 — Событийный результат интервью на продуктивность

Статус: `implemented_partially`.

## Основание

Пользователь подтвердил событийную схему: оператор нажимает результат по конкретному кандидату; массовая рассылка на этом шаге не выполняется. Пользователь также передал ссылки на две внутренние темы Telegram-группы:

- `Прошёл продуктивность`: `https://t.me/c/4397133749/1071`, topic id `1071`;
- `Кадровый резерв`: `https://t.me/c/4397133749/1073`, topic id `1073`.

## Что изменено

- нажатие `Прошёл` переводит кандидата в `productivity_passed`, отправляет ему персональное подтверждение и пишет служебную запись в тему `1071`;
- нажатие `Не прошёл` переводит кандидата в `productivity_failed` и отправляет личное предложение кадрового резерва с кнопками `Да, в кадровый резерв` / `Нет, спасибо`;
- ответ `Да` переводит кандидата в `talent_pool`, подтверждает ответ и пишет запись в тему `1073`;
- ответ `Нет` переводит кандидата в существующий статус `rejected`, не удаляя карточку и историю;
- добавлен отдельный этап доски `Кадровый резерв`;
- доставка использует идемпотентные ключи: повторное нажатие не должно дублировать уже отправленные сообщения;
- добавлен защищённый операторский запуск тестовых сообщений в обе темы без затрагивания кандидатов.

## Сохранено

- предыдущие статусы и ручное изменение остальных статусов;
- автоматические этапы до интервью на продуктивность;
- расписание вторник/пятница и слоты 11:00, 11:30, 12:00, 12:30 МСК;
- Анкета 2, Тест 1, Google Drive и существующая переписка;
- старый сценарий `not_passed` для других исторических кампаний;
- запрет на массовую отправку в рамках этого события.

## Проверка

- выполнена проверка синтаксиса изменённых JavaScript-файлов;
- проверены существующие тесты транспорта Telegram и обработка ручного результата;
- после публикации отправлены два тестовых сообщения только во внутренние темы `1071` и `1073`;
- не выполнено: нажатие живой кнопки у реального кандидата и живой ответ `Да`/`Нет` на предложение кадрового резерва.
